# ADR-001: Angular 22 and Nx Workspace Strategy

## Status

Selected Target Architecture

## Context

This decision applies the approved requirements and target enterprise policy without changing existing business API contracts.

## Decision

- Use Angular 22 as the target frontend framework.
- Use strict TypeScript for application and test code.
- Use an Nx workspace with one initial Angular application and governed libraries.

## Alternatives Considered

- None.

## Why Selected

- Angular 22 is the approved modernization target.
- Typed implementation protects the approved API and UI contracts.
- Five domains, reusable UI, and future applications justify scalable organization and affected build/test orchestration without making Nx technically mandatory.

## Consequences

- Modern standalone and signal-first APIs
- Safer refactoring
- Typed API integration
- Boundary enforcement
- Reusable libraries
- Affected execution

## Tradeoffs

- Requires current tooling and team enablement
- Strict models require discipline
- Additional tooling and governance
