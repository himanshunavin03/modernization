# ADR-005: Routing and Performance Boundaries

## Status

Selected Target Architecture

## Context

This decision applies the approved requirements and target enterprise policy without changing existing business API contracts.

## Decision

- Use Angular Router for application navigation.
- Lazy-load route-level Feature entry points.
- Use route and library boundaries for intentional code splits.
- Use @defer for noncritical dashboard regions when measured UX supports it.

## Alternatives Considered

- None.

## Why Selected

- Approved Features map cleanly to route ownership.
- Five Feature domains create intentional code-splitting boundaries.
- Feature structure provides natural loading boundaries without invented metrics.
- Independent summary regions can render progressively.

## Consequences

- Native lazy loading and guards
- Reduced initial bundle
- Bundle discipline
- Progressive loading

## Tradeoffs

- Routes require governance
- Poor chunking can delay navigation
- Too many chunks add overhead
- Placeholder behavior needs design
