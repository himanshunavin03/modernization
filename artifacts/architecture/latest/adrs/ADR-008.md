# ADR-008: Security and Correlated Observability

## Status

Selected Target Architecture

## Context

This decision applies the approved requirements and target enterprise policy without changing existing business API contracts.

## Decision

- Use functional guards where approved access policy applies.
- Propagate approved organization context through Angular, gateway, and BFF.
- Define CSP, XSS, CSRF, secure configuration, secrets, and dependency scanning controls.
- Correlate frontend, gateway, BFF, and API diagnostics without selecting a vendor.

## Alternatives Considered

- Authentication Provider (REQUIRES_CLARIFICATION): Identity and claims APIs are known, but the target provider and protocol are not approved.

## Why Selected

- They align with standalone routing while identity-provider details remain open.
- Organization context is an approved dependency across integration boundaries.
- Exact controls depend on the authentication/session decision.
- Target layers require latency and error visibility across boundaries.

## Consequences

- Composable access checks
- Consistent tenant scope
- Defense in depth
- Faster diagnosis

## Tradeoffs

- Server authorization remains authoritative
- Server policy must prevent client trust escalation
- Environment-specific validation
- Privacy and volume need governance
