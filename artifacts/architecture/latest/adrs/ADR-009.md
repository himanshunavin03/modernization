# ADR-009: Testing, Accessibility, and Delivery Quality

## Status

Selected Target Architecture

## Context

This decision applies the approved requirements and target enterprise policy without changing existing business API contracts.

## Decision

- Use semantic HTML, keyboard support, focus management, accessible forms, and automated plus manual checks.
- Test state, services, components, and accessibility at focused boundaries.
- Use Playwright for AC-traceable end-to-end journeys.
- Run lint, format, tests, builds, E2E, and security checks with affected execution where valid.

## Alternatives Considered

- None.

## Why Selected

- Accessibility must be designed and validated rather than assumed.
- Layered tests provide fast feedback before E2E.
- Approved AC provide observable browser and API-backed behavior.
- Nx can optimize feedback while full release gates remain mandatory.

## Consequences

- Inclusive interaction
- Fast defect localization
- Real browser validation
- Efficient validation

## Tradeoffs

- Formal compliance requires completed validation
- Requires stable boundaries
- Higher execution cost
- Affected checks cannot replace release validation
